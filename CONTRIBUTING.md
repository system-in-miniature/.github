# Contributing to System-in-Miniature

Thank you for helping make infrastructure mechanisms easier to inspect and
learn.

## Ways to contribute

- Report a behavior that differs from the real system without being documented.
- Fix a correctness bug or clarify an intentional simplification.
- Improve mapping, differences, bilingual documentation, examples, or labs.
- Add focused tests that make a semantic contract executable.

For behavior mismatches, use the organization's **Semantic divergence**
issue form when available. A useful report includes the project and version,
the smallest reproducible example, the observed behavior, the real-system
behavior or reference, and whether the difference is currently documented.

## Pull requests

1. Open an issue first for changes that materially alter scope or public
   semantics.
2. Keep each pull request focused on one coherent change.
3. Update tests and the relevant mapping or differences documentation when
   behavior changes.
4. Run the repository's documented test and lab commands.
5. Explain intentional simplifications explicitly; do not imply production
   compatibility that the teaching kernel does not provide.

Project repositories may add more specific contribution instructions. Those
instructions take precedence for that project.

By participating, you agree to follow the
[Code of Conduct](CODE_OF_CONDUCT.md).
